# Spec 01 — CI GitHub Actions (phase 0)

> Rédigée le 2026-11-02. État : **reportée par D34 (2026-11-02)** ; reprise avec le test Joigny.
> Branche : à recréer à la reprise.
> Décision liée : D33 (dépôt privé gratuit, pas de protection de branche).

## 1. But

Chaque PR et chaque poussée sur `main` lancent automatiquement le lint, les types, les tests et un build. Une CI rouge se voit sur la PR avant la fusion.

## 2. Décisions

- **Pas de blocage technique de la fusion (D33).** Sur un compte personnel gratuit, un dépôt privé n'a ni protection de branche ni rulesets (doc GitHub lue le 2026-11-02). La CI informe, Brainditech ne fusionne pas en rouge. La case du PLAN est réécrite en conséquence (§4).
- **Un seul job, des étapes séparées** : `npm ci` une seule fois, puis lint → types → tests → build, chacune visible à part dans l'onglet Checks. C'est moins de minutes que quatre jobs qui réinstallent chacun `node_modules`.
  - Écarté : quatre jobs parallèles (plus rapide en temps réel, mais chaque job refait `npm ci`, soit environ 4 fois plus de minutes facturées).
- **« Build » = `npx expo export --platform android`** : construit le bundle JavaScript de l'app (Metro), ce qui attrape les imports cassés et les erreurs de configuration Expo sans Gradle.
  - Écarté : `./gradlew assembleDebug` après `expo prebuild` (Java et SDK Android à installer, 10 à 20 min par exécution, budget de 12 $/mois vite entamé). Le build natif reste local (D22) ; il sera prouvé par la spec 02 (development build).
  - La sortie `dist/` est déjà ignorée par git ; elle n'est pas conservée comme artefact (stockage limité à 500 Mo).
- **Versions épinglées** (jamais `latest`, invariant 17) :
  - runner `ubuntu-24.04` (pas `ubuntu-latest`) ;
  - Node `22` (LTS du PLAN) par `actions/setup-node` ;
  - actions épinglées par **SHA de commit complet**, avec la version en commentaire : `actions/checkout` v7.0.1 et `actions/setup-node` v7.1.0 (dernières publiées, lues le 2026-11-02 sur l'API GitHub). Le SHA est relevé au moment d'écrire le fichier. Un SHA ne peut pas être déplacé, une étiquette si.
- **Économie de minutes** : cache npm de `setup-node`, `concurrency` qui annule l'exécution précédente de la même PR, `timeout-minutes: 15`.
- **Droits minimaux** : `permissions: contents: read`. Aucun secret : la CI n'appelle ni Claude ni Sentry (PLAN §3).
- **Déclencheurs** : `pull_request` (vers `main`) et `push` sur `main`.

## 4. Case du PLAN réécrite (D33)

Avant :
> CI GitHub Actions (lint, types, tests, build), avec la fusion bloquée si rouge (protection de `main` à vérifier, R8). Preuve : une PR bloquée par une CI rouge volontaire.

Après :
> CI GitHub Actions (lint, types, tests, build) sur chaque PR et sur `main`. Pas de blocage technique de la fusion (D33) : on ne fusionne jamais en rouge. Preuve : une PR d'essai avec un test rouge volontaire, échec visible sur la PR (lien), jamais fusionnée ; puis la PR de cette spec, verte.

Aucun écran touché.

## 6. Sécurité

- Aucun secret dans le workflow ni dans les journaux de la CI.
- `pull_request` (et non `pull_request_target`) : une PR n'a pas accès aux secrets ni aux droits d'écriture.
- Actions tierces épinglées par SHA : une étiquette déplacée ne peut pas injecter de code.
- `npm ci` respecte `package-lock.json` (aucune version flottante en CI).

## 7. Critères d'acceptation

1. Sur la PR de cette spec, le check `verifications` est vert, avec les étapes lint, types, tests et build visibles séparément.
2. Une PR d'essai (branche `essai/ci-rouge`, un test volontairement faux dans `src/domaine/verdict.test.ts`) affiche le check rouge à l'étape tests. Elle est fermée sans fusion et la branche supprimée.
3. Le workflow ne contient ni `latest`, ni étiquette d'action non épinglée, ni secret.
4. Durée d'une exécution relevée et consignée dans ETAT (pour le budget de minutes).

## 8. Étapes de vérification

1. Claude : `npx expo export --platform android` en local, pour vérifier que le build passe avant de pousser.
2. Claude : écrit le workflow, pousse `phase-0/ci` (avec ton accord), tu ouvres la PR, le check doit passer au vert.
3. Claude : pousse `essai/ci-rouge` ; tu ouvres la PR d'essai, on constate le rouge, tu la fermes sans fusion.
4. Liens des deux exécutions consignés dans ETAT, case cochée.
